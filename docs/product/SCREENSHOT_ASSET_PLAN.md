# Screenshot Asset Plan

Last reviewed: 2026-09-28

## Purpose
Use visuals to make a bounded, human-reviewable claim about a specific Nova build. Screenshots
are useful UI evidence; they are not release, security, authority, privacy, or outcome proof.

## Core Screenshots
1. Main dashboard
2. Trust Review Card
3. Runtime truth panel
4. Everyday useful task
5. Blocked or approval-gated action

## Placement
- README top section
- Product docs
- Release posts

## Rules

- Show reality, not mockups.
- Store the source SHA, artifact identifier/hash when applicable, date, environment, operator,
  and claimed UI behavior beside each capture.
- Capture the relevant approval/blocked boundary and receipt where the claim involves governed
  execution; redact sensitive data.
- Label captures that lack an exact revision as historical visual evidence.
- Do not use a screenshot to claim that a route is secure, an artifact is reproducible, a
  capability is broadly authorized, or an external effect occurred. Pair it with the appropriate
  test, receipt, artifact, and environment evidence.
