## Mechanism addendum (post-diagnosis, 2026-07-14)

The Section 4 "Misroutes" framing for turns 4, 5, 7, and 8 is now materially inaccurate and is
corrected here by code evidence. Those turns did **not** misroute to a wrong capability. They
most likely routed correctly into the bounded advisory general-chat LLM, and the frontend then
misrendered a backend progress frame as a hard failure.

Trace:

- On the advisory-LLM fallback, the backend emits a progress frame
  `{"type": "status", "status": "thinking", "message": "Thinking...", "phase": "llm_inference"}`
  ([session_handler.py:4352](../../nova_backend/src/websocket/session_handler.py)).
- The frontend WebSocket `switch (msg.type)` in
  [dashboard-chat-news.js](../../nova_backend/static/dashboard-chat-news.js) has cases for
  `weather`, `news`, `search`, `chat`, `chat_stream`, `chat_done`, `error`, and ~30 widget
  types, but **no `case "status"`**. The frame falls to `default: renderUnsupportedWidgetEvent`,
  which — because `rawType === "status"` — prints
  `"I couldn't retrieve connection status right now. Nothing was executed."` labeled
  `Request not run`.
- Local inference had actually started. On CPU it is slow, so the turn then hung and required
  Stop. The "connection status" copy was never about connectivity; it was a mislabeled
  "thinking" frame.

This also explains the typo sensitivity: `look up ...` (turn 6) matched the `search` widget path
and rendered correctly, while `look uo ...` (turn 5) missed the keyword, fell to advisory, and
hit the same status-frame misrender.

Classification correction:

- Turns 4, 5, 7, 8 should be read as **truth-integrity failures** (UI asserts "Nothing was
  executed" while inference has started), not capability misroutes.
- This violates the project's own "never present inference/status as fact" posture and is the
  first-ranked candidate for a freeze-exempt truth fix: add a frontend `case "status"` that
  updates the thinking/loading indicator and appends no failure message.

The `Gotcha. What should I continue from?` open-loop (turn 1) is a separate, still-unexplained
issue and is not addressed by this addendum.
